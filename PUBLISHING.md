# Release Publishing

Repository: <https://github.com/1Z99/r36s-tv>. The user-facing entry point is a
single generated **Install 227 TV.sh**, launched from the games card's Tools
folder. Do not distribute the unexpanded `install227tv.sh` template as that file.

## Verify Source

Use a clean, reviewed source tree with the tested ARM64 artifacts present.
Python 3.10+, a native C compiler, SDL2/SDL2_ttf, compatible host libmpv, `flock`,
and FFmpeg are needed for the complete offscreen host suite. Package operations
in tests are mocked; tests do not install APT packages or connect to a handheld.

```sh
bash build_globe_filter.sh /tmp/libtvglobe-host.so
SDL_VIDEODRIVER=dummy SDL_RENDER_DRIVER=software TV_MEDIA_AO=null \
  TV227_GLOBE_FILTER=/tmp/libtvglobe-host.so python3 -B -m unittest discover -v
sh -n install227tv.sh
sh -n install.sh
sh install.sh --list-runtime
```

Build the host helper at the explicit temporary path, not over the shipped
`native/libtvglobe.so`, which must remain AArch64. Normal builds use checked-in
assets; do not run the optional asset regeneration tool during routine tests.

## Build Tagged Assets

Update `VERSION` in `tv_installer.py` for a new release. Do not overwrite a
published release with newly generated bytes: publish a new version instead.
From the project root, with its parent directory already present:

```sh
python3 -B build_release.py --output ../227-tv-release-public \
  --base-url https://github.com/1Z99/r36s-tv/releases/download/v1.0.0/
```

This validates the runtime file hashes/allowlist and ARM64 globe helper, creates
the application's file-hash manifest, and produces:

- `Install 227 TV.sh`: standalone bootstrap with manager SHA-256 and size pins.
- `melkor227-tv-manager-1.0.0.tar.gz`: graphical installer and required assets.
- `melkor227-tv-1.0.0-darkosre-arm64.tar.gz`: full application and private runtime.
- Both archives' `.sha256` files and `release.json` with exact sizes/hashes.
- Installation/publishing documentation alongside the downloads.

The bootstrap pins the manager; the manager pins the full application. Keep all
files from the same build together and never edit archives after generating the
bootstrap. SHA-256 pins rely on obtaining the bootstrap from a trusted source;
they are not an independent cryptographic publisher signature.

## Publish With GitHub CLI

Only publish when explicitly authorized. Review `git status`, `git diff`, and
recent commits; do not include saved data, logs, credentials, or private keys.
Commit/push the reviewed source before tagging it. Example first release:

```sh
gh release create v1.0.0 --repo 1Z99/r36s-tv --draft \
  --target main --title '227 TV v1.0.0' --notes-file RELEASE_NOTES.md
gh release upload v1.0.0 --repo 1Z99/r36s-tv \
  '../227-tv-release-public/Install 227 TV.sh' \
  ../227-tv-release-public/*.tar.gz ../227-tv-release-public/*.sha256 \
  ../227-tv-release-public/release.json ../227-tv-release-public/INSTALLATION.md
gh release view v1.0.0 --repo 1Z99/r36s-tv --json assets
gh release edit v1.0.0 --repo 1Z99/r36s-tv --draft=false --latest
```

GitHub normalizes spaces in release asset names, currently to periods. Verify
the reported download URL for `Install.227.TV.sh` before using it in the README.
The installer works under either name and creates its own properly spaced Tools
shortcut. The project source archive alone is not the one-file installer.

## Release Acceptance

Download all publicly hosted assets again to a separate directory. Verify their
hashes and sizes against the generated script and `release.json`. Extract the
application, validate its manifest, and check that all original artwork/font
notices and mpv corresponding source/build materials are present.

On supported hardware, test the one-file Tools flow, explicit card selection,
installation, playback/audio/controls, return to ES, update preserving saved
data, and uninstall preserving other 227 apps. `release_smoke.py` can exercise
temporary-card install/update/uninstall without opening a display or modifying
the real ES config:

```sh
python3 -B release_smoke.py --release-dir /path/to/release \
  --modules /path/to/melkor227-tv
```

It checks dependencies read-only and needs supported ARM64 firmware for the
bundled runtime. A host offscreen run or historical source deployment is not
proof that the public single-script flow works on a fresh card. Record any
untested hardware steps honestly in release notes. Never start TV or its manager
in the background beside a running EmulationStation display.

## Licensing And Support

Review [CREDITS.md](CREDITS.md). The application contains MIT-licensed sources
and original artwork, but the complete distribution includes a GPL-enabled mpv
runtime and separately licensed fonts. Preserve `runtime/sources/`, build data,
and `runtime/licenses/` in releases. The retained original runtime recipe uses
soname symlinks; shipped soname files are regular copies for exFAT compatibility.

Only Debian 13 arm64 dArkOSRE is the current binary target. Do not advertise
older ArkOS, Ubuntu, AmberELEC, 32-bit images, or arbitrary clones without matching
runtime builds, platform policy changes, and hardware verification.
